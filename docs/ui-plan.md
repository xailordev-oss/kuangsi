## 2. User flow ຫຼັກ 3 ອັນ

### 2.1 ຈອງ online ຈົນໄດ້ QR — ເປົ້າ ≤ 4 ຂັ້ນ

```
[ໜ້າຫຼັກ] ──ຈອງປີ້ເລີຍ──▶ ① ວັນທີ + ປີ້ ──▶ ② ຂໍ້ມູນຜູ້ຈອງ ──▶ ③ ສະຫຼຸບ + ວິທີໂອນ ──ຢືນຢັນ──▶ ④ ການຈອງຂອງຂ້ອຍ

④ ການຈອງຂອງຂ້ອຍ (ໜ້າດຽວ ປ່ຽນຕາມ bookings.status):

  pending (ໂມງ 30 ນາທີ) ──ອັບໂຫຼດຫຼັກຖານ──▶ verifying (ໂມງຢຸດ, expires_at = NULL) ──ອະນຸມັດ──▶ paid → QR ✅
     │  ▲                                        │
     │  └──── ປະຕິເສດ (+ເຫດຜົນ) ─ ໂມງ 30 ນາທີໃໝ່ ─┘
     └── ໝົດເວລາ ──▶ expired (ປ່ອຍບ່ອນຄືນ)
```
ບໍ່ມີທາງເລືອກ "ຈ່າຍເງິນສົດ" ຝັ່ງ online ເລີຍ (ຂໍ້ຕົກລົງ 14) — ເງິນສົດມີແຕ່ POS.

| ຂັ້ນ | ສິ່ງທີ່ຜູ້ໃຊ້ເຮັດ | ⚠️ ຈຸດທີ່ມັກຖອນຕົວ | ວິທີຫຼຸດ |
|---|---|---|---|
| ① | ເລືອກວັນ, ກົດ +/− ປີ້ | ວັນທີ່ຢາກໄປ ຂາຍໝົດ/ປິດ · ສັບສົນ 6 ປະເພດປີ້ | ປະຕິທິນສະແດງວັນເຕັມ/ປິດ ລ່ວງໜ້າ (ບໍ່ໃຫ້ເລືອກແລ້ວຈຶ່ງບອກ) · ເລືອກ ລາວ/ຕ່າງປະເທດ ກ່ອນ (§3.2) |
| ② | ກອກຟອມ | ເບີໂທຕ່າງປະເທດຮູບແບບຕ່າງກັນ · ຄິດວ່າຕ້ອງໃສ່ passport | ມີຕົວເລືອກລະຫັດປະເທດ · ໝາຍ "ບໍ່ບັງຄັບ" ຊັດ ແລະ ພັບຊ່ອງເລກບັດໄວ້ |
| ③ | ກວດ + ຢືນຢັນ | ຕົກໃຈລາຄາລວມ · ບໍ່ມີແອັບທະນາຄານ / ຢາກຈ່າຍສົດ | ສະແດງລາຄາລວມຕັ້ງແຕ່ຂັ້ນ ① (sticky bar) · ອະທິບາຍຂັ້ນຕອນໂອນ **ກ່ອນ** ກົດຢືນຢັນ — ຄົນທີ່ໂອນບໍ່ໄດ້ຈະຮູ້ກ່ອນສ້າງການຈອງ (ຫຼີກເວັ້ນການຈອງຄ້າງ 30 ນາທີ) ແລະ ບອກວ່າຊື້ຢູ່ປະຕູໄດ້ |
| ④ | ໂອນເງິນຜ່ານແອັບທະນາຄານ ແລ້ວກັບມາອັບໂຫຼດ | **ສູງສຸດ**: ສະຫຼັບແອັບແລ້ວບໍ່ກັບມາ · ໝົດ 30 ນາທີ · ກັງວົນຕອນລໍກວດ | ໂມງນັບຖອຍຫຼັງ · ປຸ່ມ copy ເລກບັນຊີ · ລິ້ງໜ້ານີ້ສົ່ງທາງ SMS/ອີເມວ (Phase 7) · ອັບໂຫຼດແລ້ວໂມງຢຸດ ແລະ ບອກຊັດວ່າ "ບໍ່ໝົດອາຍຸລະຫວ່າງກວດ" |

ໝາຍເຫດ: ຜູ້ໃຊ້ກົດ 4 ຂັ້ນ ແຕ່ QR ຈະອອກ **ຫຼັງພະນັກງານອະນຸມັດ** — ເວລາລໍຂຶ້ນກັບພະນັກງານ ບໍ່ແມ່ນ UI.

### 2.2 ຂາຍປີ້ຢູ່ປະຕູ (POS) — ເປົ້າ ≤ 30 ວິນາທີ/ກຸ່ມ

```
ເລືອກ ລາວ/ຕ່າງປະເທດ (ຈື່ຄ່າກ່ອນໜ້າ) → ແຕະ +/− ປຸ່ມໃຫຍ່ → [ຮັບເງິນ] → ໃສ່ເງິນທີ່ຮັບ (ປຸ່ມລັດ 50k/100k/ພໍດີ) → ເຫັນເງິນທອນ → [ຢືນຢັນ + ພິມ]
```

| ວິນາທີ | ຂັ້ນ | ⚠️ ຈຸດຊ້າ |
|---|---|---|
| 0–10 | ເລືອກປີ້ | ຖາມອາຍຸເດັກ → ສະແດງຊ່ວງອາຍຸໃຕ້ປຸ່ມ |
| 10–20 | ຮັບເງິນ/ທອນ | ຄິດເງິນທອນ → ລະບົບຄິດໃຫ້ |
| 20–30 | ພິມ | printer ຊ້າ/ບໍ່ພ້ອມ → ສະແດງ QR ເທິງຈໍໃຫ້ລູກຄ້າຖ່າຍຮູບແທນໄດ້ |

- ຫົວຈໍ POS ໃຊ້ `StaffHeader` ດຽວກັບໜ້າສະແກນ: ຊື່ພະນັກງານ + ປຸ່ມ **"ອອກຈາກລະບົບ"** ເຫັນຊັດທີ່ມຸມຂວາເທິງ (ຂໍ້ຕົກລົງ 21)
- ບໍ່ຖາມຊື່/ເບີໂທ ເປັນຄ່າເລີ່ມຕົ້ນ → `customer_id = NULL` (ຂໍ້ຕົກລົງ 16)
- ມີລິ້ງພັບໄວ້ "ເພີ່ມຊື່ / ເບີໂທ (ບໍ່ບັງຄັບ)" — ຖ້າໃສ່ → ສ້າງ ຫຼື ໃຊ້ customer ເກົ່າຕາມເບີໂທ
- ສ້າງການຈອງ `channel = 'gate'`, `status = 'paid'`, `created_by = ພະນັກງານ`, payment `method = 'cash'`

- (Phase 8 · ຂໍ້ຕົກລົງ 41) online ເທົ່ານັ້ນ: ເນັດຂາດ → ແຖບແດງ "ເນັດຂາດ — ຂາຍປີ້ບໍ່ໄດ້ຊົ່ວຄາວ" + ປິດປຸ່ມ "ຮັບເງິນ"
- ເນັດຂາດກາງທາງຕອນກົດຢືນຢັນ → "ບໍ່ແນ່ໃຈວ່າບັນທຶກສຳເລັດບໍ່" + ປຸ່ມດຽວ "ລອງສົ່ງອີກຄັ້ງ" (requestId ເດີມ → ບໍ່ຂາຍຊ້ຳ) · ລັອກຟອມ ຫ້າມແກ້ການຂາຍທີ່ອາດບັນທຶກແລ້ວ

- ໃບປີ້ສະແດງເທິງຈໍ: ເງິນທອນ (ໃຫຍ່) · QR · ລະຫັດຈອງ · ປະເພດປີ້ · ປຸ່ມ "ພິມປີ້" (browser) + "ຂາຍໃໝ່" — TODO: ຢືນຢັນເຄື່ອງພິມ (ຂໍ້ຕົກລົງ 42)

- **Q2** ລາຄາມີຜົນເມື່ອໃດ? (a) ທັນທີທີ່ບັນທຶກ · ການຈອງໃຊ້ລາຄາ **ຕອນຈອງ** (ຄືດຽວນີ້ ບໍ່ແກ້ schema) ·
  (b) ຕັ້ງລາຄາລ່ວງໜ້າຕາມ **ວັນເຂົ້າຊົມ** (ເຊັ່ນ ໄຕມາດໜ້າ) — ຕ້ອງເພີ່ມຕາຕະລາງ `ticket_prices` (ແກ້ schema) — ແນະນຳ: (a) ສຳລັບ v1
  ຜົນຂອງ (a): ຄົນທີ່ຈອງລ່ວງໜ້າ 90 ວັນ ກ່ອນຂຶ້ນລາຄາ ຈ່າຍລາຄາເກົ່າ
- **Q3** ລະຫັດ / ກຸ່ມ / ກຸ່ມອາຍຸ ລັອກຫຼັງສ້າງ (ຢາກປ່ຽນ = ສ້າງປະເພດໃໝ່ ແລ້ວປິດອັນເກົ່າ) — ແນະນຳ: ລັອກ


### 3.9 Phase 11 — ຍົກເລີກ + ຄືນເງິນ — ⏳ wireframe ລໍອະນຸມັດ (ຍັງບໍ່ໄດ້ຂຽນ code)

ກະທົບເງິນ (ຂໍ້ຕົກລົງ 37) · ທຸກການຍົກເລີກ / ຄືນເງິນ ບັນທຶກເຫດຜົນ + audit · ນະໂຍບາຍອ່ານຈາກ `refund_policies` ສະເໝີ (ຂໍ້ຕົກລົງ 53)

#### ⚠ ຕ້ອງອະນຸມັດ schema ກ່ອນ (ພາກ 4: ຫ້າມແກ້ schema ໂດຍບໍ່ຖາມ)

ດຽວນີ້ **ບໍ່ມີຕາຕະລາງ `refund_policies`** — ມີແຕ່ `settings.refund_full_hours = 24` / `refund_half_hours = 12` ເຊິ່ງ % (100 / 50) ຝັງຢູ່ໃນຊື່ key
→ ຖ້າໃຊ້ຕໍ່ ຈະ hardcode 100% / 50% ໃນ code. ຍັງບໍ່ມີບ່ອນເກັບ "ລໍຄືນເງິນ" ແລະ ເລກບັນຊີລູກຄ້າ. ສະເໜີແກ້ `db/kuangsi-schema.sql` (ຍັງບໍ່ມີຂໍ້ມູນຄືນເງິນຈິງ — ບໍ່ສູນຫາຍຫຍັງ):

```sql
-- ນະໂຍບາຍເປັນຂັ້ນ: ຍົກເລີກກ່ອນເວລາເປີດຂອງວັນເຂົ້າຊົມ ≥ hours_before → ຄືນ refund_percent · ບໍ່ເຂົ້າຂັ້ນໃດ = 0%
CREATE TABLE refund_policies (
  id             BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
  hours_before   SMALLINT UNSIGNED NOT NULL,
  refund_percent TINYINT UNSIGNED  NOT NULL CHECK (refund_percent <= 100),
  updated_by     BIGINT UNSIGNED NULL,   -- FK users RESTRICT (ພາກ 4)
  updated_at     DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  UNIQUE KEY uk_refund_policy_hours (hours_before)
);
-- seed = ຄ່າປັດຈຸບັນ: (24, 100), (12, 50) · ລຶບ settings.refund_full_hours / refund_half_hours (ບໍ່ມີ code ໃຊ້)

-- 1 ການຄືນເງິນ ຕໍ່ 1 payment (UNIQUE) — ກັນຄືນຊ້ຳ
CREATE TABLE refunds (
  id              BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
  booking_id      BIGINT UNSIGNED NOT NULL,          -- FK RESTRICT
  payment_id      BIGINT UNSIGNED NOT NULL,          -- FK RESTRICT
  amount          DECIMAL(12,2) NOT NULL,            -- snapshot ຕອນຍົກເລີກ (ແກ້ນະໂຍບາຍພາຍຫຼັງ ບໍ່ກະທົບ)
  refund_percent  TINYINT UNSIGNED NOT NULL,
  policy_hours    SMALLINT UNSIGNED NULL,            -- ຂັ້ນທີ່ໃຊ້ · NULL = ພະນັກງານກຳນົດເອງ
  method          ENUM('cash','bank_transfer') NOT NULL,
  status          ENUM('requested','completed') NOT NULL DEFAULT 'requested',
  reason          VARCHAR(255) NOT NULL,
  requested_by    BIGINT UNSIGNED NULL,              -- NULL = ລູກຄ້າຍົກເລີກເອງ · FK users RESTRICT
  bank_name       VARCHAR(100) NULL,                 -- ບັນຊີລູກຄ້າ (ສະເພາະໂອນຄືນ)
  account_number  VARCHAR(50)  NULL,                 -- ລ້າງເປັນ NULL ທັນທີທີ່ຄືນສຳເລັດ
  account_name    VARCHAR(150) NULL,
  account_last4   CHAR(4)      NULL,                 -- ເກັບໄວ້ອ້າງອີງຫຼັງລ້າງ
  completed_by    BIGINT UNSIGNED NULL,              -- FK users RESTRICT
  completed_at    DATETIME NULL,
  transfer_ref    VARCHAR(100) NULL,                 -- ເລກອ້າງອີງການໂອນຄືນ (ບັງຄັບເມື່ອ method = bank_transfer)
  created_at      DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  UNIQUE KEY uk_refunds_payment (payment_id),
  CHECK (amount >= 0)
);

ALTER TABLE bookings ADD cancelled_at DATETIME NULL, ADD cancelled_by BIGINT UNSIGNED NULL, ADD cancel_reason VARCHAR(255) NULL;
-- cancelled_by NULL + cancelled_at ມີຄ່າ = ລູກຄ້າຍົກເລີກເອງ · FK users RESTRICT
ALTER TABLE payments ADD CHECK (refund_amount IS NULL OR (refund_amount >= 0 AND refund_amount <= amount));
```
`payments.refund_amount / refund_reason / refunded_at / status='refunded'` ຕັ້ງຕອນ **ຄືນເງິນສຳເລັດ** ເທົ່ານັ້ນ → `lib/admin/stats.ts` (ຂໍ້ຕົກລົງ 44) ໃຊ້ໄດ້ໂດຍບໍ່ແກ້

| **ກັນຄືນຊ້ຳ / ຄືນເກີນ** | ① transaction ລັອກແຖວ booking + payment (`FOR UPDATE`) — ຍົກເລີກໄດ້ສະເພາະ status `pending`/`paid` → ກົດ 2 ເທື່ອ ອັນທີ 2 ເຫັນ `cancelled` → 409 ② `UNIQUE(payment_id)` ໃນ `refunds` — DB ຫ້າມແຖວທີ 2 ③ ຈຳນວນ ≤ ຍອດທີ່ຈ່າຍຈິງ (`payments.amount` ຂອງແຖວ success) ກວດໃນ code + `CHECK` ໃນ DB ④ ຂັ້ນ "ຄືນສຳເລັດ" ເປັນ `UPDATE … WHERE status = 'requested'` (ກົດຊ້ຳ = 0 ແຖວ → ບໍ່ບັນທຶກຊ້ຳ) ⑤ test ກົດພ້ອມກັນ 2 ເທື່ອ |
| **ຄືນບາງສ່ວນໄດ້ບໍ່** | **ໄດ້ ແຕ່ຄັ້ງດຽວ** ຕໍ່ການຈອງ: ລູກຄ້າ = % ຕາມນະໂຍບາຍ (ເຊັ່ນ 50%) · admin = ຕາມນະໂຍບາຍ / 100% / ຈຳນວນໃດກໍໄດ້ 0 → ຍອດທີ່ຈ່າຍ (+ເຫດຜົນ) · ຄືນຫຼາຍເທື່ອ (ຄືນເພີ່ມພາຍຫຼັງ) ບໍ່ໄດ້ ໃນ v1 · ປັດລົງເປັນກີບເຕັມ (ບໍ່ຄືນເກີນນະໂຍບາຍ) |
| **ເງິນສົດ vs ໂອນ** | **ວິທີຄືນ = ວິທີທີ່ຈ່າຍມາ** · ເງິນສົດ (POS): cashier ຍື່ນເງິນຄືນທັນທີ → `completed` ໃນຂັ້ນດຽວ (refunded_at = ຕອນນັ້ນ) ເງິນໃນລິ້ນຊັກກົງ · ໂອນ: ຍົກເລີກ → `requested` (ລໍຄືນ) → cashier/admin ໂອນຈາກທະນາຄານ ແລ້ວໃສ່ເລກອ້າງອີງ → `completed` |
| **ເລກບັນຊີລູກຄ້າ: ເກັບໃສ ດົນປານໃດ** | ລູກຄ້າໃສ່ຕອນຍົກເລີກ (ຊື່ທະນາຄານ · ເລກບັນຊີ · ຊື່ບັນຊີ) → ເກັບໃນ `refunds` · ເຫັນສະເພາະ admin + cashier (ຄືຂໍ້ຕົກລົງ 29) · **ລ້າງເລກບັນຊີທັນທີທີ່ຄືນສຳເລັດ** ເຫຼືອແຕ່ 4 ຕົວທ້າຍ (ບໍ່ຕ້ອງມີ cron) · ຫ້າມຢູ່ໃນລາຍງານ / CSV / audit (audit ເກັບແຕ່ 4 ຕົວທ້າຍ) |
| **ນັບວັນທີຄືນເງິນ (ຂໍ້ຕົກລົງ 44)** | **ຢືນຢັນ** — ນັບຕາມ `payments.refunded_at` = ເວລາທີ່ເງິນອອກແທ້ (ໂອນສຳເລັດ / ຍື່ນເງິນສົດ) **ບໍ່ແມ່ນ** ເວລາກົດຍົກເລີກ · ລາຍງານວັນທີ່ຜ່ານມາບໍ່ປ່ຽນ · ຍອດທີ່ "ລໍຄືນ" (requested) ຍັງບໍ່ນັບເປັນຄືນເງິນ → ສະແດງແຍກໃນ dashboard ເປັນ "ຄ້າງຄືນ X ກີບ (n)" |

ການຄິດນະໂຍບາຍ: ຊົ່ວໂມງທີ່ເຫຼືອ = (ວັນເຂົ້າຊົມ + ເວລາ**ເປີດ**ຂອງວັນນັ້ນ, ເວລາລາວ) − ເວລາກົດຍົກເລີກ → ເລືອກຂັ້ນທີ່ `hours_before` ສູງສຸດ ທີ່ ≤ ຊົ່ວໂມງທີ່ເຫຼືອ → %
ຕົວຢ່າງ (seed): ເຫຼືອ 30 ຊມ → 100% · 15 ຊມ → 50% · 5 ຊມ → 0% · ຄິດທີ່ server ເທົ່ານັ້ນ ແລະ snapshot ລົງ `refunds`

ສະຖານະກ່ອນຍົກເລີກ:
| status | ລູກຄ້າ | admin | ຄືນເງິນ |
|---|---|---|---|
| `pending` (ຍັງບໍ່ຈ່າຍ) | ✅ | ✅ | ບໍ່ມີເງິນຕ້ອງຄືນ — ຍົກເລີກຢ່າງດຽວ |
| `verifying` (ລໍກວດຫຼັກຖານ) | ❌ "ລໍພະນັກງານກວດກ່ອນ" | ❌ ໃຫ້ອະນຸມັດ/ປະຕິເສດກ່ອນ | — (ກັນກໍລະນີເງິນເຂົ້າແລ້ວແຕ່ບໍ່ມີແຖວ success) |
| `paid` | ✅ ຕາມນະໂຍບາຍ | ✅ | ຕາມ % |
| `used` / `expired` / `cancelled` | ❌ | ❌ | — |
