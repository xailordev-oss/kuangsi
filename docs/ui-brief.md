# UI/UX Brief — ລະບົບຈອງປີ້ຕາດກວາງຊີ

> **ສຳລັບ AI agent**: ໄຟລ໌ນີ້ບອກວ່າຕ້ອງສົ່ງ **ແຜນອອກແບບ** ຫຍັງມາໃຫ້ອະນຸມັດ
> ຂັ້ນຕອນນີ້ **ຫ້າມຂຽນ code, ຫ້າມສ້າງ component, ຫ້າມຕິດຕັ້ງ package**
> ສົ່ງມາເປັນເອກະສານ + wireframe ແບບ ASCII/markdown ເທົ່ານັ້ນ

---

## 1. ຂໍ້ຈຳກັດທີ່ຕາຍຕົວ (ຫ້າມປ່ຽນ)

### 1.1 Mobile-first — ບັງຄັບ
ນັກທ່ອງທ່ຽວຈອງຈາກໂທລະສັບຢູ່ໂຮງແຮມ ຫຼື ລະຫວ່າງເດີນທາງ. ອອກແບບ **ຈໍ 375px ກ່ອນ** ແລ້ວຄ່ອຍຂະຫຍາຍ.

| Breakpoint | ຂະໜາດ | ໃຊ້ສຳລັບ |
|---|---|---|
| `base` | 375px | ໂທລະສັບ (ຕົ້ນຕໍ) |
| `md` | 768px | ແທັບເລັດ |
| `lg` | 1024px+ | ຄອມ (ສ່ວນໃຫຍ່ແມ່ນ admin) |

### 1.2 ຕົວອັກສອນລາວ — ຈຸດທີ່ມັກຜິດ

ອັກສອນລາວມີສະຫຼະ ແລະ ວັນນະຍຸດ **ວາງຊັ້ນເທິງ-ລຸ່ມ** ຖ້າໃຊ້ `line-height` ປົກກະຕິ (1.2–1.4) ວັນນະຍຸດຈະຖືກຕັດ ຫຼື ຊ້ອນກັນ.

```css
/* ບັງຄັບໃຊ້ຄ່າເຫຼົ່ານີ້ສຳລັບຂໍ້ຄວາມລາວ */
font-family: 'Noto Sans Lao', 'Phetsarath OT', sans-serif;
line-height: 1.8;        /* ຢ່າໃຊ້ຕ່ຳກວ່າ 1.7 */
```

- **ຫ້າມ** `text-align: justify` — ພາສາລາວບໍ່ມີຍະຫວ່າງລະຫວ່າງຄຳ ການຕັດແຖວຈະຜິດ
- **ຫ້າມ** column ແຄບເກີນ (ຕ່ຳກວ່າ 280px) ເພາະຕັດແຖວຜິດຕຳແໜ່ງ
- ປຸ່ມ ແລະ ປ້າຍ: ຢ່າຕັ້ງຄວາມສູງຕາຍຕົວ ໃຊ້ padding ແທນ
- ຂໍ້ຄວາມລາວຍາວກວ່າອັງກິດປະມານ 10–20% — ເວັ້ນທີ່ໄວ້

### 1.3 ຫຼາຍພາສາ
ລາວ (ຄ່າເລີ່ມຕົ້ນ) · ອັງກິດ · ຈີນ · ໄທ — ປຸ່ມປ່ຽນພາສາຢູ່ມຸມຂວາເທິງ ເຫັນໄດ້ທຸກໜ້າ

### 1.4 ການເຂົ້າຖຶງ (Accessibility)
- ປຸ່ມແຕະໄດ້ຕ່ຳສຸດ **44×44px**
- ຄວາມຕ່າງສີ (contrast) ຕ່ຳສຸດ **4.5:1**
- ຢ່າໃຊ້ສີຢ່າງດຽວບອກສະຖານະ — ໃສ່ icon ຫຼື ຂໍ້ຄວາມນຳ

## 2. ສິ່ງທີ່ຕ້ອງສົ່ງມາໃຫ້ອະນຸມັດ (6 ລາຍການ)

### 2.1 ລາຍການໜ້າ + route

ສົ່ງເປັນຕາຕະລາງ: route · ຊື່ໜ້າ · ໃຜເຂົ້າໄດ້ · ຈຸດປະສົງ

ໜ້າທີ່ຕ້ອງມີຢ່າງໜ້ອຍ:

**ຝັ່ງລູກຄ້າ**
- ໜ້າຫຼັກ (ແນະນຳຕາດ + ປຸ່ມຈອງ + ໄລຍະທາງຈາກຕຳແໜ່ງຂອງຜູ້ໃຊ້)
- ເລືອກວັນທີ ແລະ ຈຳນວນປີ້
- ກອກຂໍ້ມູນຜູ້ຈອງ
- ສະຫຼຸບ + ຢືນຢັນ
- ຈ່າຍເງິນ
- ສຳເລັດ (ສະແດງ QR + ລະຫັດຈອງ)
- ຄົ້ນຫາປີ້ຂອງຂ້ອຍ (ດ້ວຍລະຫັດຈອງ + ເບີໂທ)

**ຝັ່ງພະນັກງານ**
- ເຂົ້າສູ່ລະບົບ
- ສະແກນປີ້ (ເຕັມຈໍ ໃຊ້ມືດຽວໄດ້)
- ຂາຍປີ້ຢູ່ປະຕູ (ໄວ ປຸ່ມໃຫຍ່)

**ຝັ່ງ Admin**
- Dashboard
- ຈັດການປີ້/ລາຄາ · ການຈອງ · ຜູ້ໃຊ້ · ລາຍງານ · ຕັ້ງຄ່າ

### 2.2 User flow ຫຼັກ 3 ອັນ

ຂຽນເປັນຂັ້ນຕອນ ພ້ອມບອກວ່າຂັ້ນໃດຜູ້ໃຊ້ມັກຖອນຕົວ:

1. **ຈອງ online ຈົນໄດ້ QR** — ຕັ້ງເປົ້າ **ບໍ່ເກີນ 4 ຂັ້ນຕອນ**
2. **ຂາຍປີ້ຢູ່ປະຕູ** — ຕັ້ງເປົ້າ **ບໍ່ເກີນ 30 ວິນາທີ/ຄົນ**
3. **ສະແກນປີ້ເຂົ້າ** — ຕັ້ງເປົ້າ **ບໍ່ເກີນ 3 ວິນາທີ/ຄົນ**

### 2.3 Wireframe ແບບ ASCII

ສຳລັບ 5 ໜ້າສຳຄັນ (ໜ້າຫຼັກ · ເລືອກປີ້ · ສະຫຼຸບ · ສຳເລັດ+QR · ສະແກນ) ສົ່ງມາແບບນີ້:

```
┌─────────────────────────┐
│ ☰   ຕາດກວາງຊີ      ລາວ▾│
├─────────────────────────┤
│                         │
│    [ ຮູບຕາດ ]           │
│                         │
│  📍 ທ່ານຢູ່ຫ່າງ 31 ກມ    │
│     ປະມານ 50 ນາທີ        │
│                         │
│  ┌───────────────────┐  │
│  │   ຈອງປີ້ເລີຍ      │  │
│  └───────────────────┘  │
└─────────────────────────┘
```

### 2.4 Design tokens

ສະເໜີມາເປັນຕາຕະລາງ ພ້ອມເຫດຜົນສັ້ນໆ:

- **ສີຫຼັກ** — ແນະນຳໂທນ turquoise/ຟ້າອ່ອນ ຕາມສີນ້ຳຂອງຕາດ
- **ສີສະຖານະ** — ສຳເລັດ / ລໍຖ້າ / ຜິດພາດ / ຍົກເລີກ
- **ຕົວອັກສອນ** — ຂະໜາດ 4–5 ລະດັບ (ບໍ່ຕ່ຳກວ່າ 16px ສຳລັບເນື້ອຫາ)
- **ຍະຫວ່າງ** — ໃຊ້ scale ຂອງ Tailwind
- **ມຸມໂຄ້ງ ແລະ ເງົາ** — ເລືອກ 2–3 ລະດັບ ຫ້າມເກີນ

### 2.5 ບັນຊີ component

ແຍກເປັນ 2 ກຸ່ມ:
- **ເອົາຈາກ shadcn/ui ໂດຍບໍ່ແກ້** — Button, Input, Dialog, Calendar...
- **ຕ້ອງສ້າງເອງ** — ເຊັ່ນ `TicketQuantityPicker`, `DistanceCard`, `QrTicket`, `ScannerView`

ສຳລັບແຕ່ລະອັນທີ່ສ້າງເອງ ບອກ: props · ສະຖານະ · ໃຊ້ຢູ່ໜ້າໃດ

### 2.6 ສະຖານະຂອງທຸກໜ້າ (ຢ່າລືມ 5 ອັນນີ້)

ສຳລັບແຕ່ລະໜ້າ ບອກວ່າຈະສະແດງຫຍັງຕອນ:

| ສະຖານະ | ຕົວຢ່າງ |
|---|---|
| ກຳລັງໂຫຼດ | skeleton ຫຼື spinner |
| ວ່າງເປົ່າ | "ຍັງບໍ່ມີການຈອງ" |
| ຜິດພາດ | ຂໍ້ຄວາມພາສາລາວ + ປຸ່ມລອງໃໝ່ |
| ສຳເລັດ | ຢືນຢັນຊັດເຈນ |
| ຂັດຂ້ອງ | ປີ້ໝົດ / ຕາດປິດ / ປີ້ຖືກໃຊ້ແລ້ວ |

## 3. ຂໍ້ຄວາມ UI (ຂຽນເປັນພາສາລາວກ່ອນ)

ສົ່ງມາເປັນຕາຕະລາງ `key | ລາວ | English`:

```
booking.cta              | ຈອງປີ້ເລີຍ                      | Book now
booking.select_date      | ເລືອກວັນທີເຂົ້າຊົມ               | Select visit date
booking.sold_out         | ປີ້ວັນນີ້ຂາຍໝົດແລ້ວ              | Sold out for this date
scan.success             | ປີ້ຖືກຕ້ອງ ເຂົ້າໄດ້              | Valid — allow entry
scan.duplicate           | ປີ້ນີ້ຖືກໃຊ້ແລ້ວ                 | Already used
distance.away            | ທ່ານຢູ່ຫ່າງ {km} ກມ              | {km} km away
```

**ກົດການຂຽນຂໍ້ຄວາມ:**
- ບອກສິ່ງທີ່ຕ້ອງເຮັດ ບໍ່ແມ່ນບອກລະຫັດຜິດພາດ
- ຂໍ້ຄວາມ error ຕ້ອງບອກ **ວິທີແກ້** ບໍ່ແມ່ນພຽງບອກວ່າຜິດ
- ຫຼີກເວັ້ນຄຳສັບ IT ("validation failed", "token expired")

## 4. ຈຸດທີ່ຕ້ອງອອກແບບໃຫ້ລະອຽດກວ່າປົກກະຕິ

**ໜ້າເລືອກຈຳນວນປີ້** — ມີ 6 ປະເພດ (ລາວ/ຕ່າງປະເທດ × ຜູ້ໃຫຍ່/ເດັກ/ຟຣີ) ຖ້າວາງບໍ່ດີຈະສັບສົນຫຼາຍ. ຄິດວ່າຈະໃຫ້ຜູ້ໃຊ້ເລືອກ "ຄົນລາວ ຫຼື ຕ່າງປະເທດ" ກ່ອນ ແລ້ວຈຶ່ງສະແດງແຕ່ 3 ປະເພດ ຫຼື ສະແດງທັງ 6 ພ້ອມກັນ — ສະເໜີມາພ້ອມເຫດຜົນ.

**ໜ້າສະແກນປີ້** — ພະນັກງານຖືໂທລະສັບມືດຽວ ຢູ່ກາງແດດ:
- ຜົນການສະແກນຕ້ອງເຫັນຈາກໄກ (ສີຂຽນເຕັມຈໍ = ຜ່ານ, ແດງ = ບໍ່ຜ່ານ)
- ຕ້ອງມີສຽງ ຫຼື ສັ່ນ ປະກອບ
- ປຸ່ມສຳຄັນຢູ່ເຄິ່ງລຸ່ມຂອງຈໍ (ນິ້ວໂປ້ເອື້ອມເຖິງ)
- ຕ້ອງໃຊ້ໄດ້ຕອນເນັດຂາດ (offline queue)

**ໜ້າ QR ຂອງລູກຄ້າ** — ຕ້ອງເບິ່ງໄດ້ offline (ເພາະຢູ່ຕາດສັນຍານອ່ອນ) ແລະ ມີລະຫັດຈອງເປັນຕົວເລກໃຫ້ອ່ານໄດ້ດ້ວຍຕາ ເພື່ອສຳຮອງຕອນສະແກນບໍ່ໄດ້.

## 4b. ຂໍ້ຕົກລົງທີ່ກະທົບ UI (ຕັດສິນແລ້ວ — ອອກແບບຕາມນີ້)

- **1 QR ຕໍ່ 1 ການຈອງ** — ໜ້າ QR ສະແດງ "ຜູ້ໃຫຍ່ 2 · ເດັກ 1" ໃຫ້ພະນັກງານນັບກຸ່ມ ບໍ່ແມ່ນ QR ຕໍ່ຄົນ
- **ຈອງແບບ guest** — ຫ້າມມີໜ້າສະໝັກສະມາຊິກ ຫຼື ປຸ່ມ login ຝັ່ງລູກຄ້າ
- **ລາຄາເປັນກີບຢ່າງດຽວ** — ຖ້າສະແດງ USD/THB ໃຫ້ສະແດງເປັນຕົວເລກຮອງ ພ້ອມໝາຍວ່າ "ປະມານ"
- **ຍັງບໍ່ມີຮອບເວລາ** ໃນ v1 — ເລືອກແຕ່ວັນທີ ບໍ່ຕ້ອງອອກແບບຕົວເລືອກຮອບ
- **ຈ່າຍເງິນ v1** = ຈ່າຍໜ້າງານ ຫຼື ອັບໂຫຼດຮູບຫຼັກຖານໂອນ → ຕ້ອງອອກແບບ:
  - ໜ້າອັບໂຫຼດຮູບ (ຖ່າຍຈາກກ້ອງ ຫຼື ເລືອກຈາກຄັງຮູບ)
  - ສະຖານະ "ລໍພະນັກງານກວດ" ໃຫ້ລູກຄ້າເຫັນຊັດ
  - ໜ້າພະນັກງານກວດຫຼັກຖານ (ເຫັນຮູບ + ປຸ່ມອະນຸມັດ/ປະຕິເສດ)
- **`id_number` ບໍ່ບັງຄັບ** — ຢ່າເຮັດໃຫ້ຄືວ່າຕ້ອງໃສ່
